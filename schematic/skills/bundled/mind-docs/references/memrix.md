# Memrix 场景

## What

`Memrix` 是性能采样与趋势解释对象，用来回答“资源有没有持续变差，流畅度有没有抖”。

一句话区分：

- `Memrix` 看趋势、基线、回归。
- `Framix` 看用户体感和画面阶段。

## When To Use

- 你要判断内存是否持续抬升。
- 你要看某条业务路径的 FPS、掉帧、卡顿趋势。
- 你要做启动、滚动、切页后的资源基线留档。

## When Not To Use

- 你想直接知道哪一段画面最慢。
- 你只是要处理视频文件。
- 你只想做单次协议请求校验。

## Decision Table

| 输入情况 | 推荐模式 |
| --- | --- |
| 临时采样或直接出最近一次报告 | `mind --chat --helix` |
| 需要开始采样、执行业务路径、结束采样、生成报告 | `mind --plan --helix` |
| 只做体感阶段判断 | 转到 [Framix 场景](framix.md) |

## Core Rules

- 任务最好写成 4 步：开始采样、执行业务路径、结束采样、生成报告。
- 不是只看某个瞬时值，而是看趋势和路径。
- 一次说清采样对象、观察路径、关注指标和输出要求。
- 使用策略要与当前工具集对齐：开始采样、执行业务路径、结束采样、生成报告是分阶段能力，示例里不要把它们压成一句模糊的“看看性能”。
- 示例应强调采样对象、业务路径、观察指标和最终报告，而不是展开 token、scene 或分层参数。

## Good Examples

```bash
mind --plan --helix "开始采集内存，目标是 com.example.app。重复执行首页到详情页再返回首页的业务流。结束内存采样。生成内存报告，判断多轮后是否持续抬升。"
```

```bash
mind --plan --helix "开始采集流畅度，目标是 com.example.app。执行进入首页、向下滚动列表 3 次、停留 2 秒、返回顶部这条路径。结束流畅度采样。生成流畅度报告，关注 FPS、掉帧和卡顿趋势。"
```

补充示例：

```bash
mind --plan --helix "开始采集内存，目标是 com.example.app；执行首页到详情页再返回首页的业务流；结束采样后生成内存报告，判断多轮后是否持续抬升，并返回证据路径。"
```

```bash
mind --plan --helix "开始采集图形性能，目标是 com.example.app；执行进入首页、向下滚动列表 3 次、停留 2 秒、返回顶部这条路径；结束采样后生成流畅度报告，重点看 FPS、掉帧和卡顿趋势。"
```

```bash
mind --chat --helix "基于已有的 Memrix 结果直接生成报告，不重新采样；如果是内存场景，给出是否持续抬升的结论；如果是图形场景，给出 FPS 和 jank 趋势摘要。"
```

## Bad Examples

```bash
mind --chat --helix "看下性能。"
```

问题：

- 没说采谁。
- 没说跑哪条路径。
- 没说看内存还是流畅度。
- 没说最后要报告还是只看趋势。

## Checklist

- 是否写清采样对象和业务路径。
- 是否区分内存采样和流畅度采样。
- 是否要求报告结论和证据路径。
- 是否避免把 `Memrix` 和 `Framix` 混用。
- 示例是否拆成了“开始采样 / 执行业务路径 / 结束采样 / 生成报告”的自然阶段。

## Failure Handling

- 只开始采样未执行路径时，明确指出结论不完整。
- 需要用户体感阶段结论时，切到 [Framix 场景](framix.md)。
