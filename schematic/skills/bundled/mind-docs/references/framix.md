# Framix 场景

## What

`Framix` 是录屏真值分析对象，用来回答“用户到底看到了什么，慢在画面的哪一段”。

一句话区分：

- `Framix` 解释体感和画面阶段。
- `Memrix` 解释资源趋势和流畅度信号。

## When To Use

- 你已经有问题录屏，想快速定位最慢阶段。
- 你要把“感觉慢”落成阶段帧报告。
- 你要比较启动、切页、流式输出这些用户可见过程。

## When Not To Use

- 你只是要裁剪视频、抽关键帧、转码或探测文件信息。
- 你要解释内存抬升、FPS 抖动、卡顿趋势。
- 你没有任何录屏或视频证据，却想做帧级结论。

## Decision Table

| 输入情况 | 推荐模式 |
| --- | --- |
| 已有录屏，直接分析 | `mind --chat --helix` |
| 需要先录再分析 | `mind --plan --helix` |
| 只做文件处理，不做真值分析 | 转到 [Media 场景](media.md) |

## Core Rules

- 一次说清分析对象、阶段路径、关注指标和输出要求。
- `Framix` 属于本地工具链；已有本地视频时直接写文件路径，不要用云端附件承载视频输入。
- 没有显式文件路径时，也可以走本地分析链路的内部回填；但不要把它表述成云端接收附件。
- 重点指标通常是 E2E、首字上屏、尾字上屏、流式 tokens、切换速度。
- 要求输出最慢区间、阶段结论和证据路径。
- 没有录屏时，不要硬做帧级结论。
- 使用策略要与当前工具集对齐：已有视频直接分析、先录再分析、只基于已有结果生成报告，是三种不同入口，示例里要把意图写清楚。

## Good Examples

```bash
mind --chat --helix "分析本地录屏文件 ./artifacts/perf/home_to_detail.mp4，路径是首页到详情页。重点看端到端耗时、首字上屏和尾字上屏，定位最慢阶段，并生成阶段帧报告和证据路径。"
```

```bash
mind --plan --helix "开始一段覆盖完整交互流程的录屏。打开 com.example.app 并进入目标页面。完成一次首页到详情页的典型操作。停止录制。基于这段录屏生成 Framix 阶段报告，重点看端到端耗时、首字上屏、尾字上屏和流式 tokens。"
```

补充示例：

```bash
mind --chat --helix "直接分析本地录屏 ./artifacts/perf/home_to_detail.mp4，重点看首页到详情页这条路径的端到端耗时、首字上屏和尾字上屏；返回最慢阶段、关键帧结论和证据路径。"
```

```bash
mind --chat --helix "基于已经完成的 Framix 分析结果生成最终报告，不重跑视频分析；输出阶段结论、最慢区间和可回看的证据路径。"
```

## Bad Examples

```bash
mind --chat --helix "帮我看下这个视频。"
```

问题：

- 没说看哪条路径。
- 没说看什么指标。
- 没说要什么结果形态。

```bash
mind --chat --helix "分析这段首页到详情页的录屏，重点看端到端耗时、首字上屏和尾字上屏，定位最慢阶段，并生成阶段帧报告。" --attach ./artifacts/perf/home_to_detail.mp4
```

问题：

- `Framix` 不走云端附件输入。
- 本地视频应直接写文件路径，不要用 `--attach`。

## Checklist

- 是否提供了录屏或明确先录再分析。
- 若已有视频输入，是否在任务正文里直接给出本地文件路径。
- 是否指定了阶段路径和指标。
- 是否要求返回最慢区间、关键结论和证据路径。
- 是否避免把 `Framix` 当成通用视频处理器。
- 示例是否区分了“直接分析视频”“先录再分析”“只出报告”三种入口。

## Failure Handling

- 没有视频证据时，明确指出无法做帧级结论。
- 需要资源趋势解释时，切到 [Memrix 场景](memrix.md)。
