# 高质量任务 Rubric

## What

这份文档定义“一个任务写得够不够好”的统一标准。

它不是某个场景的说明书，而是所有场景都要先过的一道质量门。

## When To Use

- 你写完一条任务，想判断它是否已经可执行。
- 模型输出总是空泛、无阈值、无产出。
- 你要把一个模糊需求改写成可验收任务。

## Decision Table

| 检查维度 | 达标标准 | 常见失败信号 |
| --- | --- | --- |
| 目标 | 明确写出要完成什么 | “看看”“测一下”“处理一下” |
| 范围 | 写清对象、页面、接口、文件、时间段 | 对象不明、路径不明、输入不明 |
| 通过条件 | 有状态码、字段、阈值、页面条件、退出码 | 只说“成功即可” |
| 产出 | 有摘要、证据路径、日志、截图、提取字段 | 没写返回什么 |
| 边界 | 写清只读/可改、不要碰哪里、失败是否停止 | 默认让模型自由发挥 |
| 回退 | 失败时有原因、已尝试、下一步建议 | 只说“失败了” |

## Core Rules

- 没有目标和范围的任务，不算任务。
- 没有通过条件的任务，不算可验收任务。
- 没有产出的任务，不算可交付任务。
- 没有边界的任务，默认风险过高。
- 没有失败回报的任务，不能进入稳定回归。

## Good Examples

```bash
mind --fast --mcp "对 https://api.example.com/orders?page=1 做 GET，校验状态码 200，断言 list 为数组且 total_count 大于 0，提取 first_order_id、total_count 和 trace_id，并返回摘要。"
```

```bash
mind --chat --mcp "启动 xx 应用，进入登录页，输入测试账号密码并点击登录；等待首页主标题出现；若失败立即截图并导出日志；返回通过/失败结论、失败步骤和证据路径。"
```

## Bad Examples

```bash
mind --xtra "帮我看一下。"
```

问题：

- 没目标。
- 没范围。
- 没产出。

## Checklist

- 是否明确目标。
- 是否限定范围。
- 是否定义通过条件。
- 是否定义产出。
- 是否写出边界。
- 是否写出失败时的回报。

## Failure Handling

- 如果一条任务有 2 项以上 checklist 不满足，先不要执行，先重写。
- 如果你不知道该补哪一项，去看 [任务写法反模式](task-writing.md) 找对照问题。
