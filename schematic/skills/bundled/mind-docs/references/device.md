# Device 场景

## What

`Device` 负责把真机或 UI 交互任务写成可执行巡检，而不是一句“帮我点一下页面”。

它覆盖：

- 启动应用。
- 页面操作。
- 条件等待。
- 截图取证。
- 导出日志。
- 系统按键与系统面板操作。
- 设备状态快照。

## When To Use

- 你要做页面交互或巡检。
- 你需要截图、日志和失败步骤。
- 你要把一条操作路径固化成证据链。
- 你要打开通知栏、快捷设置、回到桌面或做系统级前置动作。
- 你要在关键步骤保存截图或设备状态。

## When Not To Use

- 你只是要做接口调用，不涉及页面交互。
- 你没有页面路径和成功条件，只是在泛泛描述“测一下页面”。
- 你真正关心的是资源趋势或录屏真值，应转到 `Memrix` 或 `Framix`。

## Decision Table

| 任务形态 | 推荐写法重点 |
| --- | --- |
| 单页面检查 | 写清页面入口、可见元素和成功条件 |
| 多步巡检链路 | 写清动作顺序、每步成功标志、失败是否即停 |
| 需要证据链 | 补截图、日志、失败步骤和证据路径 |
| 需要后续性能分析 | 明确是否同时保留录屏或日志用于 `Framix` / `Memrix` |

## Core Rules

- 写清起点：应用、页面、前置状态。
- 写清动作链：点击、输入、滚动、返回、确认。
- 写清成功条件：标题出现、按钮可点、列表加载、提示消失。
- 写清失败处理：立即截图、导出日志、返回失败步骤。
- 如果路径较长，优先把每步写成“动作 + 成功标志”。
- 如果页面元素可能变更，尽量写用户可感知的成功条件，而不是过度依赖内部名词。
- 使用策略要与当前工具集对齐：应用控制、页面交互、元素等待、截图取证、日志导出、系统按键/面板、设备状态快照是分开的能力，不要把它们压扁成一句“自动测页面”。
- 示例里优先写“动作 + 成功标志 + 失败证据”，而不是展开定位字段或设备选择参数。

## Good Examples

```bash
mind --plan "启动 xx 应用，进入登录页，输入测试账号密码并点击登录；等待首页主标题出现；若失败立即截图并导出日志；返回通过/失败结论、失败步骤和证据路径。"
```

```bash
mind --chat "打开商品列表页，向下滚动直到出现‘推荐商品’分区，点击第一项进入详情页，等待价格和购买按钮出现，返回截图与关键页面状态。"
```

```bash
mind --plan "启动 xx 应用，进入设置页，依次检查网络、通知、隐私三个入口是否可见且可点击；每步失败立即截图并导出日志；返回通过项、失败项和证据路径。"
```

补充示例：

```bash
mind --plan "先把 com.example.app 拉到前台并进入登录页；输入测试账号和密码后点击登录；等待首页主标题出现；若失败立即导出关键日志并返回失败步骤与证据路径。"
```

```bash
mind --chat "在商品列表页持续向下滚动，直到‘推荐商品’分区进入可视区域；点击第一项进入详情页，等待价格和购买按钮出现，并返回关键页面状态与截图。"
```

```bash
mind --plan "先打开通知栏和快捷设置，确认 Wi-Fi 与蓝牙入口可见；再回到桌面并启动目标应用；若任一步失败，立即保存截图并返回失败步骤与证据路径。"
```

```bash
mind --chat "先返回桌面，再打开最近任务列表确认目标应用仍在任务栈中；随后保存当前设备状态快照和截图，返回关键前台信息与证据路径。"
```

## Bad Examples

```bash
mind --chat "测一下登录页。"
```

问题：

- 没有动作链。
- 没有成功条件。
- 没有失败证据。

```bash
mind --plan "从首页随便点几下看看有没有问题。"
```

问题：

- 动作链不稳定。
- 没有明确验收目标。
- 无法沉淀为回归材料。

```bash
mind --chat "帮我按几个系统键，然后看看设备有没有问题。"
```

问题：

- 没说按哪些系统键。
- 没说要验证什么结果。
- 没说是否需要截图、状态快照或失败证据。

## Checklist

- 是否写清起点和页面路径。
- 是否写清动作链。
- 是否写清成功条件。
- 是否写清失败后的截图和日志。
- 多步任务是否写清每步成功标志。
- 示例是否保持在高层动作链，而不是退化成定位参数清单。
- 如果涉及系统动作，是否写清打开哪个系统面板、按哪个键、要验证什么结果。

## Failure Handling

- 失败时优先截图和导出日志。
- 多步路径失败时，返回具体失败步骤，不要只给总失败。
- 如果需要后续分析录屏或性能问题，失败时明确保留相关证据入口。
