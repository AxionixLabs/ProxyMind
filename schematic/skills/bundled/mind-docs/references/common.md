# Common 场景

## What

`Common` 解决的是通用辅助动作，不是主业务场景本身。

典型任务包括：

- 等待或轮询状态。
- 生成摘要、签名、JWT。
- 在主任务前后补充状态检查。

## When To Use

- 你需要一个辅助动作承接后续步骤。
- 你要补一个等待、轮询或安全计算动作。
- 主场景已经确定，但缺少通用收束步骤。

## When Not To Use

- 任务主体是接口验证，优先看 [Nexus 场景](nexus.md)。
- 任务主体是代码修改，优先看 [Coding 场景](coding.md)。
- 任务主体是设备巡检，优先看 [Device 场景](device.md)。

## Core Rules

- 说清楚“把结果用于什么”，不要只写“算一下”“等一下”。
- 指定输入、输出和等待条件。
- 即便是辅助步骤，也要写明最终要返回什么结论。
- 使用策略要与当前工具集对齐：固定等待归到 runtime 类能力，状态快照归到 inspect 类能力。
- 安全相关能力按职责拆开：摘要/HMAC、JWT、RSA、AES、签名文本拼装分别是不同能力，不要在自然语言里把它们混成“顺便都算一下”。
- 如果任务本质上只是声明循环步骤，要把它表达成“步骤声明”，不要写成“已经执行完所有循环”。

## Good Examples

```bash
mind --fast --mcp "等待 2 秒后继续执行下一步，并返回当前状态摘要。"
```

```bash
mind --fast --mcp "对 payload 做 SHA-256 摘要，返回十六进制结果，并说明可直接用于后续签名对比。"
```

```bash
mind --fast --mcp "轮询任务状态直到完成或超时；若完成返回最终状态和摘要，若超时返回已等待时长与当前状态。"
```

补充示例：

```bash
mind --fast --mcp "先做一次运行态状态快照，确认当前没有挂起任务；再等待 2 秒进入下一步，并返回收束前后的状态摘要。"
```

```bash
mind --fast --mcp "把这段 payload 做 SHA-256 摘要，用于后续签名对比；只返回摘要结果和用途说明。"
```

```bash
mind --fast --mcp "声明一个三轮重复的辅助步骤链：每轮先等待 1 秒，再检查当前空闲状态；这里只返回标准化步骤声明，不直接执行。"
```

## Bad Examples

```bash
mind --fast --mcp "等一下。"
```

问题：

- 没写等待对象和结束条件。
- 没写最终要返回什么。

## Checklist

- 是否写明辅助动作服务于哪个主任务。
- 是否写明输入、条件和输出。
- 是否区分单次计算和持续轮询。
- 示例是否仍然保持高层自然语言，而不是滑到参数清单或机器对象。

## Failure Handling

- 条件不足时，指出缺少的输入字段或结束条件。
- 轮询超时时，返回已等待时长和当前状态，不要只说超时。
