# UI Actions Strategy

## 定位
UI Actions 约束移动端 APP 中查找、点击、输入、滑动、导航、等待等动作。  
目标是让每个动作可控、可复现、可解释，并保留最小证据。

---

# Find 查找策略

## 目标
用最小代价把用户目标收敛为唯一、可交互、可解释的 UI 对象。

## 查找顺序
优先顺序：

```text
页面锚点
→ 精确文本 / label / desc / resource-id / accessibility id
→ 区域约束
→ 结构约束
→ 状态约束
→ 当前视口
→ 有上限滚动
→ 可回退导航
```

## 查找原则
1. 关键查找必须依赖页面锚点。
2. 锚点不成立，先回到可控页面。
3. 精确匹配优先于模糊匹配。
4. 当前视口优先于滚动查找。
5. 滚动查找必须有次数上限和停止条件。
6. 跨页面查找必须保证可回退。

## 多命中处理
多命中时按以下顺序消歧：

```text
锚点区域内
→ 当前视口
→ 可交互控件
→ 语义最接近
→ 结构位置更合理
```

仍不唯一时：

```text
不点击
不输入
只输出候选
问一个最短消歧问题
```

## 找到不等于可执行
找到目标后还必须确认：

- 是否可见
- 是否可点击
- 是否可输入
- 是否被遮挡
- 是否在当前页面锚点内
- 是否处于稳定窗口

# Click 点击策略

## 目标
点击必须满足“知道点了什么、为什么能点、点后发生什么”。

## 点击前条件
点击前必须满足：

```text
页面锚点成立
页面稳定
目标唯一
目标可见
目标可交互
目标未遮挡
```

## 风险分级

### 导航型点击
例如进入详情页、打开设置页、返回上一页。

允许相对激进，但点击后必须观察页面锚点变化。

### 交互型点击
例如切换开关、选择选项、展开折叠区。

要求目标唯一，点击后必须观察状态变化。

### 关键型点击
例如提交、删除、支付、退出登录、覆盖数据、清空数据。

要求：

```text
页面锚点成立
目标唯一
用户意图明确
禁止模糊点击
禁止坐标兜底
```

## 点击后判断
点击后只要求最小证据变化，不做冗长验收。

可接受证据：

- 页面锚点变化
- 弹窗出现或消失
- 按钮状态变化
- 文本状态变化
- 列表内容变化
- 页面跳转完成

## 点击失败处理
点击后无变化时：

```text
不连点
→ 判断是否遮挡
→ 判断是否未稳定
→ 判断是否误命中
→ 必要时回锚点
→ 最多一次有限重试
```

# Input 输入策略

## 目标
输入是数据写入，必须保证目标输入框明确、焦点明确、内容落位明确。

## 输入前条件
必须满足：

```text
页面锚点成立
目标输入框唯一
输入框可见
输入框可编辑
输入框已聚焦或可聚焦
无弹窗/键盘遮挡关键目标
```

## 标准链路
```text
确认页面
→ 定位输入框
→ 聚焦
→ 清空
→ 写入
→ 确认落位
→ 用户明确要求时才提交
```

## 多输入框处理
多输入框场景必须使用语义槽位消歧。

常见槽位：

- 用户名
- 密码
- 手机号
- 邮箱
- 验证码
- 搜索框
- 备注
- 地址
- 订单号

歧义时：

```text
不写入
只定位候选
问一个最短消歧问题
```

## 输入后证据
输入后至少确认一种证据：

- 明文内容可见
- 输入框状态变化
- 字符长度变化
- 焦点仍在目标框
- 密码框可确认已输入但不要求读取明文
- 搜索结果或联想列表变化

## 输入失败处理
最多一次重聚焦重发。  
仍失败则停止，并输出：

```text
输入失败：
- 输入框：
- 失败表现：
- 可能原因：
- 下一步：
```

常见原因：

- 控件不可编辑
- 被键盘遮挡
- 被弹窗遮挡
- 输入法异常
- WebView 焦点异常
- 密码框不可读
- 非标准控件

# Swipe / Scroll 滑动策略

## 目标
滑动是视窗控制，不是查找替代品。  
滑动必须有方向、上限和停止条件。

## 滑动前定义
必须明确：

```text
滚动区域
方向
次数上限
停止条件
```

## 停止条件
可用停止条件：

- 目标出现且可交互
- 到达顶部或底部
- 页面锚点变化异常
- 超过滚动次数上限
- 目标区域不再变化
- 出现阻断弹窗

## 每次滑动后
必须执行：

```text
等待稳定
→ 检查页面锚点
→ 查找目标
→ 命中即停
```

## 禁止行为
- 无限滚动
- 未定义方向就滑
- 未定义停止条件就滑
- 用长距离滑动替代精确查找
- 在关键表单页面盲目滑动导致数据丢失

---

# Navigation 导航策略

## 目标
导航路径必须可回退、可复现、可解释。

## 原则
每跳一层都要：

```text
等待稳定
→ 检查新页面锚点
→ 记录最小证据
```

## 偏航信号
以下情况视为偏航：

- 页面标题不符合预期
- 核心锚点消失
- 出现登录页
- 出现错误页
- 出现权限阻断
- 出现网络异常页
- APP 崩溃或回到桌面
- 页面长时间 loading

## 偏航处理
```text
先处理阻断
→ 回最近锚点
→ 必要时回首页
→ 必要时重启 APP
→ 仍失败则停止
```

# Wait 等待策略

## 目标
等待用于收敛不确定状态，不用于替代查找、点击或输入判断。

## 允许等待
可以等待：

- 页面锚点出现
- 页面锚点稳定
- 目标元素出现
- 目标元素可交互
- loading 消失
- 弹窗出现或消失
- 键盘出现或消失
- 输入内容落位
- 页面跳转完成
- 列表滚动停止

## 约束
1. 等待必须有硬上限。
2. 等待必须有证据目标。
3. 超时视为失败或偏航。
4. 不做无限等待。
5. 不用 sleep 替代条件等待，除非场景只需要固定观察窗口。

## 超时输出
```text
等待超时：
- 等待目标：
- 超时时长：
- 当前页面：
- 当前锚点：
- 下一步：
```
