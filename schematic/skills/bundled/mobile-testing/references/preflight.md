# Preflight Strategy

## 定位
Preflight 是设备/UI 链路的前置状态收敛策略。  
它只适用于需要操作设备、页面、APP、UI 控件的任务。

非设备链路不执行 Preflight。

## 目标
在点击、输入、滑动、录屏、日志采集、页面跳转前，确认环境处于可控状态，避免盲动、误点、误输入和污染测试现场。

## 检查顺序

```text
设备状态
→ 屏幕状态
→ APP 状态
→ 页面锚点
→ 干扰项
→ 稳定窗
→ 目标可操作性
```

## 1. 设备状态
设备必须在线并可通信。

### 检查项
- 设备是否在线
- 是否存在多设备未指定
- 是否 unauthorized
- 是否断连
- 是否响应超时
- 是否模拟器或真机状态异常

### 处理原则
设备不可通信时，停止当前 UI 链路，不继续操作。

输出：

```text
设备不可用：
- 当前状态：
- 阻塞原因：
- 下一步：
```

## 2. 屏幕状态
屏幕必须处于可交互状态。

### 检查项
- 屏幕是否点亮
- 是否已解锁
- 是否存在锁屏密码阻断
- 是否有系统遮罩
- 是否有系统弹窗
- 是否有输入法、浮层、悬浮窗遮挡

### 处理原则
可自动恢复的，先恢复到可交互状态。  
不可自动恢复的，停止并说明阻塞原因。

## 3. APP 状态
APP 必须在前台，或可以被前台化。

### 检查项
- APP 是否已安装
- APP 是否可启动
- APP 是否在前台
- 是否崩溃
- 是否卡死
- 是否白屏 / 黑屏
- 是否停留在启动页
- 是否进入错误页面

### 处理原则
APP 不在前台时，可以前台化。  
APP 崩溃、卡死、启动失败时，停止当前动作链路，输出异常。

## 4. 页面锚点
关键动作前必须确认页面锚点。

### 锚点类型
优先选择稳定、唯一、业务含义明确的特征：

- 页面标题
- 核心按钮
- 唯一文本
- 唯一区域
- 关键控件
- 页面结构特征
- 当前 activity / view controller / 页面标识

### 锚点要求
- 1 到 2 个强锚点即可
- 不做冗长验收
- 锚点不成立，不做破坏性操作
- 锚点不成立时，先回最近可控页面

## 5. 干扰项
干扰项必须先处理。

### 常见干扰
- 权限弹窗
- 升级弹窗
- 广告弹窗
- 登录过期
- 网络异常提示
- 蓝牙 / 定位 / 通知权限提示
- 键盘遮挡
- 系统浮层
- 崩溃弹窗

### 处理原则
如果干扰项属于当前测试目标的一部分，则记录并按目标处理。  
如果不是测试目标，只处理到业务链路可继续。

## 6. 稳定窗
页面必须稳定后再动作。

### 稳定判断
以下情况需要等待：

- 页面跳转中
- 动画未结束
- loading 未消失
- 列表仍在滚动
- 弹窗刚出现或刚消失
- 键盘弹起或收起中
- 输入后内容未落位
- 网络刷新中

### 超时处理
等待必须有上限。  
超时视为偏航或阻塞，不无限等待。

## 7. 目标可操作性
动作前必须确认目标可操作。

### 判断项
- 目标存在
- 目标唯一
- 目标可见
- 目标可点击或可输入
- 目标未被遮挡
- 目标位于当前可操作区域
- 当前页面锚点仍成立

## 最小证据
Preflight 不需要输出长报告，但需要保留最小证据：

```text
设备在线
APP 前台
页面锚点成立
无关键阻断
目标可操作
```

## 失败输出
Preflight 失败时输出：

```text
Preflight 阻塞：
- 阻塞位置：
- 当前状态：
- 不能继续的原因：
- 最短修复建议：
```

## 禁止行为
- 设备不可通信仍继续点
- 页面未知仍输入
- 锚点不成立仍提交
- 弹窗遮挡仍点业务控件
- 目标不唯一仍点击
- 未确认输入框焦点仍写入
- 无限等待
- 连续盲点
