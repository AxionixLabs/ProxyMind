# Failure Policy

## 目标
移动端测试失败时，必须先止损，再判断原因，再尝试有限恢复。  
禁止盲点、连点、无限等待、未知页面输入和擅自扩大副作用。

## 总原则
失败处理顺序：

```text
停止当前动作
→ 识别失败类型
→ 保留当前证据
→ 回最近锚点
→ 有限恢复
→ 最多一次重试
→ 仍失败则停止
```

## 失败类型

### 设备失败
包括：

- 设备离线
- unauthorized
- 多设备未指定
- 命令超时
- 投屏或截图失败
- 设备状态漂移

处理：

```text
停止 UI 链路
→ 输出设备状态
→ 提供最短修复建议
```

### APP 失败
包括：

- APP 未安装
- APP 启动失败
- APP 崩溃
- APP 卡死
- 白屏 / 黑屏
- 启动页长时间不动
- 被系统杀后台

处理：

```text
保留日志或截图
→ 尝试回到入口
→ 必要时重启 APP
→ 仍失败则停止
```

### 页面失败
包括：

- 页面锚点不成立
- 进入错误页面
- 登录态失效
- 网络错误页
- 页面长时间 loading
- 弹窗阻断

处理：

```text
处理阻断
→ 回最近锚点
→ 必要时回首页
→ 仍失败则停止
```

### 目标失败
包括：

- 找不到目标
- 目标不唯一
- 目标不可见
- 目标不可点击
- 目标被遮挡
- 目标不可输入

处理：

```text
增强约束
→ 滚入视口
→ 关闭遮挡
→ 仍不唯一或不可交互则停止
```

### 输入失败
包括：

- 焦点失败
- 清空失败
- 写入失败
- 内容未落位
- 键盘遮挡
- 输入法异常
- 密码框不可读

处理：

```text
最多一次重聚焦重发
→ 仍失败则停止
```

### 等待失败
包括：

- 元素未出现
- 页面未稳定
- loading 未消失
- 弹窗未出现或未消失
- 输入未落位

处理：

```text
检查当前锚点
→ 判断是否偏航
→ 必要时回锚点
→ 不无限等待
```

## 降级策略

### 允许降级
以下降级通常允许：

- 重新查找目标
- 增加区域或结构约束
- 滚入视口
- 关闭非目标弹窗
- 返回上一页
- 回最近锚点
- 回首页
- 重启 APP

### 谨慎降级
以下操作必须谨慎：

- 坐标点击
- 强制停止 APP
- 清除缓存
- 切换网络
- 重启设备
- 删除本地数据
- 重新登录

只有用户目标明确且副作用可接受时才允许。

### 禁止降级
以下行为禁止：

- 关键操作模糊点击
- 页面未知时输入
- 目标不唯一时提交
- 未确认焦点时写入
- 连续盲点
- 无限滚动
- 无限等待
- 外部工具失败后擅自换工具重试
- 擅自清数据、卸载、支付、删除、提交

## 关键操作止损
以下操作属于关键操作：

```text
提交
删除
支付
退出登录
清空数据
覆盖配置
授权敏感权限
发送消息
下单
```

关键操作要求：

```text
用户意图明确
页面锚点成立
目标唯一
动作前可解释
动作后有证据
```

任一条件不满足，必须停止。

## 外部工具失败
外部工具失败时，以工具输出为准。

禁止：

- 换工具再试
- 主观改判
- 隐藏错误
- 编造结果
- 把失败解释成成功

输出格式：

```text
工具失败：
- 工具：
- 错误：
- 影响：
- 最短下一步：
```

## 停止条件
遇到以下情况必须停止：

- 设备不可通信
- APP 崩溃或无法启动
- 页面锚点不成立且无法恢复
- 关键目标不唯一
- 关键操作风险过高
- 输入目标不明确
- 等待超时且页面偏航
- 外部工具返回不可恢复错误
- 用户意图不明确且继续执行有副作用

## 失败输出要求
失败时不要长篇解释，直接给：

```text
失败位置
当前状态
失败原因
已保留证据
下一步建议
```
