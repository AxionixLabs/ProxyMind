# Overview

## 定位
Mobile Testing Skill 是移动端 APP 测试策略，用于指导 Agent 判断任务类型、规划测试链路、执行设备/UI 操作、采集证据、处理异常并输出简短结论。

本 Skill 只描述移动端测试通用策略，不绑定具体框架工具、循环编排器、专用分析工具或沙盒能力。

## 核心目标
移动端测试的目标不是“能点就点”，而是保证每一步：

```text
在正确设备上
在正确 APP 内
在正确页面中
对唯一目标执行动作
动作后能看到最小证据变化
失败时能及时止损
```

## 适用范围
适用于 Android / iOS 移动端 APP 的：

- 功能验证
- UI 自动化操作
- 页面跳转验证
- 登录、搜索、表单填写、权限流程等业务链路
- 启动、前后台切换、长时间驻留等移动端运行场景
- 截图、录屏、日志、报告等证据分析
- 问题复现步骤与测试结论整理

## 不适用范围
不适用于：

- 纯代码修改
- 代码仓库维护
- 通用文件处理
- 框架级宏编排
- 批量循环调度协议
- 外部工具结果的主观二次判定
- 与移动端设备或移动端证据无关的任务

## 两类链路
移动端任务优先分为两类。

### 设备/UI 链路
涉及真实设备、模拟器、页面状态、点击、输入、滑动、录屏、日志采集、前后台切换等行为。

设备/UI 链路必须先执行 Preflight。

### 非设备链路
基于已有日志、截图、录屏、报告、CSV、JSON、文本等文件进行分析、整理和总结。

非设备链路不执行 Preflight，不附加设备连接、解锁、启动 APP 等步骤。

## 执行原则
1. 设备/UI 链路先收敛状态，再执行动作。
2. 非设备链路直接基于输入分析，不强行接设备。
3. 点击、输入、滑动前必须确认页面锚点和稳定窗。
4. 关键操作必须目标唯一。
5. 找不到、目标不唯一、页面不稳定时，不盲动。
6. 失败时先止损，再回锚点，再给最短修复建议。
7. 外部工具输出以工具结果为准，不二判、不改分。
8. 最终输出要短，优先给结果、证据、失败点和下一步。

## 最小证据
每段设备/UI 链路至少保留最小证据：

```text
当前页面锚点
目标对象状态
动作后变化
异常或阻塞信息
```

不要求冗长验收，但必须能解释“为什么可以执行”和“执行后发生了什么”。

## 框架能力边界
重复执行、批量采集、宏步骤编排、任务调度、失败是否中断、批量结果聚合，属于上层框架能力。

本 Skill 不定义循环工具、不定义批跑协议、不绑定框架私有能力。  
本 Skill 只约束每一轮移动端测试应该如何判断、执行、止损和输出。
