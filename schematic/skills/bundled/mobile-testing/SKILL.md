# Mobile Testing Skill

## 目标

用于指导 Agent 执行 Android / iOS 移动端 APP 的自动化测试、UI 操作、稳定性验证、异常定位和结果汇总。

本 Skill 的目标是：最少对话，最小闭环，可执行，可复现。
当任务涉及设备、页面、点击、输入、滑动、录屏、日志采集、前后台切换等行为时，必须先进行 Preflight，再进入动作链路。

## 适用场景

* Android / iOS APP 功能验证
* 移动端 UI 自动化操作
* 启动、登录、搜索、表单填写、页面跳转等流程测试
* 权限弹窗、系统弹窗、升级弹窗、网络异常提示处理
* 启动、前后台切换、长时间驻留等移动端运行场景
* 基于已有日志、截图、录屏、报告的离线分析和结果整理
* 移动端测试结论、问题复现步骤、证据链整理

## 不适用场景

* 纯代码修改、代码仓库维护
* 与移动端设备无关的通用文件处理
* 框架级宏编排、批量循环执行、任务调度策略
* 外部工具输出的二次验收或主观改判
* 用户仅咨询概念时，不展开完整执行链路
* 缺少核心参数且无法安全推断的任务

## 全局原则

1. 设备/UI 链路默认先过 Preflight。
2. 非设备链路直接构参与执行，不附加设备连接、解锁、启动 APP 等前置步骤。
3. 能用离线文件直接闭环的，不强行接设备。
4. 点击、输入、滑动前必须确认锚点、稳定窗和目标可交互。
5. 关键操作必须唯一目标；不唯一时只定位并提出一个最短消歧问题。
6. 外部工具失败时，以工具输出为准，不擅自换工具重试。
7. 重复操作、批量执行、多轮循环属于框架编排层；本 Skill 只描述单轮移动端测试策略和证据要求。
8. 输出要短，优先给执行结果、失败点、证据和下一步。

## 链路分流

设备/UI 链路：

```text
Preflight
→ Find
→ Action
→ Wait
→ Minimal Evidence
→ Summary
```

非设备链路：

```text
Parse Input
→ Analyze / Organize
→ Summary
```

仅当用户明确要求“先设备操作，再离线分析”时，才允许串联两类链路。

## 执行口径

* 用户要求执行：按链路分流执行。
* 用户仅咨询：按分层口径解释要点，不展开长教程。
* 异步启动类任务：只启动不默认等待；用户明确要求“等待完成 / 跑完后分析 / 导出报告”时才等待。
* 多轮重复执行：交给框架编排层处理，Skill 不定义循环工具或宏步骤结构。
